# BLOG · api · 1g630rl

**Outcome.** fix lane disabled — analysed and reported, no MR

**Root cause.** getProductsGraphQL interpolates the merchant's raw `search` query param into a double-quoted GraphQL string literal (`query: "status:active ... title:*${searchQuery}*"`), so a search term containing a double quote closes that literal early and the trailing `*` is lexed as an invalid token, making Shopify reject the whole document.

**Mechanism.** GET /api/products-store passes ctx.query.search straight through as searchQuery (shopifyController.js:258,261). graphQLProducts.js:14 wraps it as `title:*<search>*` and line 19 splices the result into a GraphQL string literal that the code builds by hand instead of passing as a $variable. Reproducing the exact template: the opening `*` always lands at column 73 of query line 2 and the closing `*` at 73+1+len(searchQuery); the reported position [2, 99] fixes len(searchQuery) = 25. That trailing `*` is only an *invalid token* if the string literal is no longer open at that column, which requires an unescaped `"` inside the merchant's 25-character search text. Shopify's parser answers 400, shopify-api-node raises RequestError, the catch at graphQLProducts.js:63 is not an auth error so it logs at logger.error (line 67) and rethrows; getProductsStore's catch swallows it into `{success:false}` (shopifyController.js:269), which is why the requests read has 0 entries with status>=500 — the product picker just comes back empty for the merchant.

Confidence: `high`

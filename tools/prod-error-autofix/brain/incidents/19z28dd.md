# BLOG · api · 19z28dd

**Outcome.** MR opened: https://gitlab.com/avada/blogs/-/merge_requests/791

**Root cause.** shop.recentOpenedArticles in Firestore holds character-indexed objects instead of gid strings — written by the pre-2026-07-28 formatDateFields, which spread every array item through itself — and articleController.list passes those objects straight into getShopifyArticleById, where `id.includes('gid')` throws TypeError.

**Mechanism.** FE Blog/Edit.jsx POSTs {recentOpenedArticles: ['gid://shopify/Article/…']} to /shop (packages/assets/src/pages/Blog/Edit.jsx:157-162). updateShopData ran formatDateFields, whose array branch before commit 2dc42bd20 was `value.map(item => formatDateFields(item))`; formatDateFields does `{...data}`, so each gid STRING became `{"0":"g","1":"i","2":"d",…}` and was persisted. The write bug is fixed on master, but the corrupted docs remain, and Edit.jsx re-spreads whatever the API returns back into the next POST, so the corruption is self-sustaining per shop. On GET /api/articles?getRecentPosts=true, articleController.list reads shop.recentOpenedArticles (articleController.js:655) and maps each element into getShopifyArticleById({shop, id}) (articleController.js:662). There `id.includes('gid')` (shopifyGraphQlService.js:742) is called on the object → TypeError: id.includes is not a function. The service's own catch (shopifyGraphQlService.js:851-854) logs and returns {}, which list filters out — hence 0 request-log 5xx and a silently empty 'recently opened' list.

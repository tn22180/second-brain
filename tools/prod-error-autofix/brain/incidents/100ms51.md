# SEO · apigen2 · 100ms51

**Outcome.** smoke gate reproduce_not_failing

**Root cause.** GET /api/resource-report computes its report inline by scanning the shop's entire Shopify catalog (all 4 resource types, 250/page, no page cap and no time budget), so for large shops the request runs past apiGen2's configured timeoutSeconds: 540 and Cloud Run kills it with a 504.

**Mechanism.** packages/functions/src/routes/api.js:220 binds /resource-report to getResourceReport. On a cache miss (analysisController.js:248, TTL 10 min) the controller builds a Shopify client at analysisController.js:260 with {autoLimit: true, maxRetries: 0} and calls countResourcesWithFaq at analysisController.js:262. countResourcesWithFaq (generateBulkService.js:258) loops the 4 tabs of FAQ_GEN_TABS (generateBulkService.js:175) and, per tab, runs an unbounded `while (hasNext)` cursor walk (generateBulkService.js:266) at FAQ_SCAN_PAGE_SIZE = 250 (generateBulkService.js:182), each page one serial Admin GraphQL round-trip (generateBulkService.js:338). Nothing in that loop carries a deadline, a page cap, or a partial-result exit. The 24h request log shows the resulting latency is a continuum against the cap, not a distinct failure mode: 11 requests to this endpoint exceeded 300s on 2026-08-12 — three answered 200 at 349.620s, 435.568s and 501.684s, and the other eight were 504 at 539.945–540.000s, matching apiGen2's timeoutSeconds: 540 (handlers/exports/httpFunctions.js:41) to the millisecond. All eight 504s carry ?section=meta-title and referer https://seo.apps.avada.io/embed/ai-content, i.e. the merchant admin Report card (packages/assets/src/pages/AiContent/Report.js:29). The cache is written only after the whole scan finishes (analysisController.js:275), so a shop whose scan cannot complete under 540s never populates its cache entry and re-scans from zero on every page load — 12:14:29, 12:20:51 and 12:24:31 are three such full scans launched inside 10 minutes, overlapping in flight. That contention is visible upstream: the one application-level error the endpoint logged in 3 days is `[getResourceReport] T2H5gDwkGWqSC5T8GRS3 Throttled RequestError: Throttled` at 15:28:40Z, seconds after the 15:28:15Z 504 and two other concurrent calls — with maxRetries: 0 a throttled page kills the scan outright. The 504s themselves log nothing, which is expected: Cloud Run terminates the request before the catch at analysisController.js:292 can run.
